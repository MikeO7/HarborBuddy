Watchtower alternative

A Watchtower alternative that rolls back failed updates

HarborBuddy does the job Watchtower did: it watches the containers on a Docker host and recreates them when their images change. It adds what Watchtower never had: it waits for the new container to pass its health check, and puts the original container back automatically if the update fails.

Last reviewed November 6, 2026 against each project's own documentation.

What happened to Watchtower?

  • The original containrrr/watchtower repository was archived on December 17, 2025. Its last release, v1.7.1, shipped in November 2023.
  • Its default Docker API version, 1.25, is rejected by Docker Engine 29 with client version 1.25 is too old (issue #2124). DOCKER_API_VERSION=1.44 is a stopgap.
  • An actively maintained fork, nicholas-fedor/watchtower, keeps the same variables and labels and is a true drop-in replacement.

If you want Watchtower exactly as it was, use the fork. If you want unattended updates that check their own work, read on.

Which one should you use?

Choose HarborBuddy if

  • A broken image should never leave a service down.
  • You pull public images and read logs or use an uptime monitor.
  • You run it at home or for other noncommercial use.

Stay with the Watchtower fork if

  • You need private registry logins or built-in notifications.
  • You rely on cron schedules, the HTTP API, or opt-in labels.
  • You need a permissive open-source license for commercial use.

Migrate from Watchtower in four steps

  1. Stop Watchtower so two updaters never touch the same containers: docker compose stop watchtower.
  2. Translate your settings using the table below.
  3. Start HarborBuddy in dry-run mode and compare its plan with what Watchtower used to do.
  4. Remove dry-run, then remove the Watchtower service.

Before and after

# Before: Watchtower
watchtower:
  image: containrrr/watchtower
  volumes:
    - /var/run/docker.sock:/var/run/docker.sock
  environment:
    WATCHTOWER_SCHEDULE: "0 0 4 * * *"
    WATCHTOWER_CLEANUP: "true"
    TZ: Europe/Berlin
# After: HarborBuddy
harborbuddy:
  image: ghcr.io/mikeo7/harborbuddy:0.1
  container_name: harborbuddy
  restart: unless-stopped
  stop_grace_period: 2m
  volumes:
    - /var/run/docker.sock:/var/run/docker.sock
  environment:
    HARBORBUDDY_SCHEDULE_TIME: "04:00"
    HARBORBUDDY_TIMEZONE: Europe/Berlin
    HARBORBUDDY_CONTAINER_NAME: harborbuddy
    HARBORBUDDY_DRY_RUN: "true"
  labels:
    com.harborbuddy.role: daemon
