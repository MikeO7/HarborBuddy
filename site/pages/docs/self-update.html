Self-update

How HarborBuddy updates itself

A container cannot replace itself while it runs, so HarborBuddy starts a short-lived helper from the new image and exits. The helper runs the same staged replacement and readiness check as any other update, and restores the old daemon if anything fails.

The handoff

  1. HarborBuddy sees a new image for its own container.
  2. It starts a helper container from the new image with only what it needs to reach Docker: the socket or certificate mounts, the Docker and logging variables, and the daemon's user, groups, security options, and capabilities. With a Unix socket the helper has no network at all.
  3. The daemon exits cleanly, and the helper replaces it, keeping the old daemon as a backup until the new one is ready.

When self-update fails

If the helper fails at any point after the daemon exits, it restores the daemon's original restart policy and starts the old container again. For the next 24 hours HarborBuddy does not retry that same image and logs self_update_blocked each cycle. It tries again after that, or as soon as a different image is published. Remove the failed helper container to retry immediately.

Helpers are kept after they exit so their logs stay readable, and are removed after 7 days. List them with:

docker ps -a --filter label=com.harborbuddy.self-update-helper=true

Help HarborBuddy find itself

Set HARBORBUDDY_CONTAINER_NAME to the stable Compose container name, and always set it when managing a remote daemon. The com.harborbuddy.role=daemon label keeps an unidentified HarborBuddy container out of the ordinary update path.

Keep HarborBuddy under manual control

environment:
  HARBORBUDDY_SELF_UPDATE_ENABLED: "false"

Then update it yourself with docker compose pull harborbuddy && docker compose up -d --no-deps harborbuddy. One-shot --once runs never self-update.

Which tag to follow

The 0.1 tag follows 0.1.x patch releases, so self-update never jumps to a new minor version. Pin 0.1.0 or a digest to stop self-update entirely, follow latest for every stable release, or follow edge to track the main branch.
