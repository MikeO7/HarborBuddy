Filters and labels

Choose which containers update

Every running container is eligible by default. Narrow that with an opt-out label on individual containers, or with allow and deny patterns on image references. Deny rules always win.

Opt out one container

services:
  postgres:
    image: postgres:17
    labels:
      com.harborbuddy.autoupdate: "false"

Use this for databases and anything that needs a manual migration step after an upgrade.

Allow and deny image patterns

updates:
  allow_images:
    - "ghcr.io/my-org/*"
    - "nginx:*"
  deny_images:
    - "*:latest"
    - "postgres:*"

A pattern is an exact value or has one * at either end. Each pattern is checked against the reference as written, its short form with the implicit :latest tag, and its fully qualified form. So *:latest matches image: nginx, and nginx:* matches docker.io/library/nginx:1.27.

Opt in instead of opting out

To update only the images you list, replace the default allow_images: ["*"] with your own list. Anything that does not match is skipped and logged at debug level.

Pinned tags and digests

HarborBuddy follows the reference you wrote. A container on app:2.4 gets new 2.4 builds; one on app:2.4.1 only changes if that exact tag is rebuilt. A container started from a digest (app@sha256:…) never changes, because the digest always resolves to the same image. Containers created from a bare image ID are skipped.

Containers that are always skipped

Some containers cannot be recreated safely from Docker's inspection data. HarborBuddy skips Swarm tasks, auto-remove containers, containers that share or provide another container's namespaces (for example a VPN gateway used through network_mode: service:gluetun), and mounts it cannot reproduce. See limits and requirements.
