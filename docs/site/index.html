Self-hosted Docker container updater

Automatic Docker updates with a rollback path.

HarborBuddy keeps the containers on your Docker host up to date. It replaces a container only when its image actually changed, waits for the new one to pass its health check, and puts the original back if the update fails. Think Watchtower, with a safety net.

How it works

Pull the image. Compare IDs. Replace only when something changed.

01

Discover eligible containers

Allow and deny patterns, an opt-out label, and safety checks narrow each run to containers HarborBuddy can recreate faithfully.

02

Pull and compare image IDs

HarborBuddy pulls each container's image reference and compares immutable image IDs. Same ID, no restart.

03

Replace, check, or roll back

The original becomes a stopped backup while the replacement starts. If the replacement is not healthy in time, the original comes back.

Built for unattended runs

Safety checks before every restart.

HarborBuddy re-inspects each container before changing it, keeps the settings you chose while letting new image defaults apply, and skips anything it cannot reproduce.

Rollback

The old container stays until the new one is ready

A failed create, start, or health check restores the original container with its name, networks, and restart policy. Interrupted updates are recovered on the next run.

Self-update

A short-lived helper replaces the HarborBuddy container, checks it starts, and restores the old one if not. A bad release is not retried for 24 hours.

Before you install

Docker control is host control.

HarborBuddy needs read/write access to the Docker API, which is effectively root on the host. Run one HarborBuddy per Docker daemon. Updates cause a brief interruption, rollback is best-effort, and images that need a registry login are not supported yet. Without a Docker health check, ready means the process stayed up for two seconds.

Common questions

Questions about automatic Docker updates.

What is HarborBuddy?

HarborBuddy is a self-hosted service that keeps the containers on a Docker host up to date. It pulls each container's image reference on a schedule, replaces the container only when the image ID changed, waits for the new container to become ready, and restores the original container if the update fails.

Is HarborBuddy a Watchtower alternative?

Yes. Like Watchtower, HarborBuddy runs as a container with access to the Docker socket and recreates containers when their images change. Unlike Watchtower, it keeps the original container as a backup, waits for the replacement's health check, and rolls back automatically when an update fails. The original containrrr/watchtower repository was archived on December 17, 2025. See the Watchtower comparison and migration guide.

How does HarborBuddy decide a container needs an update?

It pulls the image reference stored in the container, such as nginx:1.27, and compares the pulled image ID with the image ID the container runs. A changed tag alone is not enough; the image itself must differ.

What happens when an updated container fails to start?

HarborBuddy removes the failed replacement, restores the original container's name, networks, and restart policy, and starts it again. It then skips that image for that container until a different image is published. Rollback is best-effort, because Docker or the host can also fail during recovery.

Does HarborBuddy work with Docker Compose?

Yes. It updates containers that Docker Compose started, keeping their names, networks, volumes, and labels. It recreates them from Docker's inspection data and never edits or rereads your Compose files.

Does an update cause downtime?

Yes, briefly. HarborBuddy stops the old container before starting its replacement, so it is not a rolling or zero-downtime updater.

Can I preview updates without changing anything?

Yes. Dry-run mode pulls images to compare real image IDs and reports what would change, but never stops, recreates, or removes a container and never deletes cleanup candidates.

How do I stop a container from updating automatically?

Add the label com.harborbuddy.autoupdate: "false" to it, or add its image to updates.deny_images, for example postgres:*. Deny rules always win over allow rules.

Does HarborBuddy send notifications?

Not yet. It writes structured text or JSON logs with stable event names, and its container health check turns unhealthy when it loses Docker or a cycle gets stuck, so log collectors and uptime monitors can alert on it.

Does HarborBuddy support Podman, Swarm, or Kubernetes?

HarborBuddy targets a standalone Docker Engine and its integration tests also run against Podman's Docker-compatible API. It skips Docker Swarm tasks and does not manage Kubernetes.

Does HarborBuddy support private registries?

Not yet. It pulls without registry credentials, so it works with public images on Docker Hub, GHCR, Quay, and other registries, but not with images that require a login.

Is HarborBuddy free?

Yes, for personal, homelab, and other noncommercial use. It is source-available under the PolyForm Noncommercial License 1.0.0; commercial use is not permitted by the current license.
