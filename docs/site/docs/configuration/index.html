Configuration reference

Configure HarborBuddy with environment variables, a YAML file, or command-line flags. Flags override environment variables, and HARBORBUDDY_* variables override YAML.

Environment variables

Booleans accept true/false, yes/no, on/off, or 1/0 in any case. Invalid values stop startup instead of silently falling back, and an unknown HARBORBUDDY_* variable logs a warning with a suggestion for common typos.

YAML file

HarborBuddy reads /config/harborbuddy.yml when it exists. Mount it read-only with ./harborbuddy.yml:/config/harborbuddy.yml:ro. Parsing is strict: unknown fields fail startup. These are the defaults:

docker:
  host: ""

updates:
  enabled: true
  check_interval: 12h
  schedule_time: ""
  timezone: UTC
  dry_run: false
  self_update: true
  allow_images: ["*"]
  deny_images: []
  stop_timeout: 10s
  startup_timeout: 30s
  rollback_image_retention: 0

cleanup:
  enabled: true
  min_age_hours: 24
  dangling_only: true
  all: false
  stopped_containers: false
  unused_networks: false
  unused_volumes: false
  build_cache: false
  # dangling_image_min_age_hours: 1
  # cache_volumes: ["*gocache", "*gomod"]
  # cache_volume_min_age_hours: 1
  # keep_images: ["openthread/border-router:*"]
  # keep_volumes: ["*-backups"]
  # keep_volume_labels: ["com.example.keep=true"]

log:
  level: info
  json: false
  file: ""
  max_size: 10
  max_backups: 1

A fuller annotated example lives in examples/harborbuddy.yml.

Schedules and timezones

With schedule_time set, HarborBuddy runs once a day at that HH:MM in the configured timezone and does not run at startup. Otherwise it runs every check_interval, starting immediately. Intervals below one minute log a warning, because every cycle pulls each eligible image and can hit registry rate limits.

The timezone comes from --timezone, then HARBORBUDDY_TIMEZONE, then updates.timezone, then TZ, then UTC. If a daylight-saving change skips the scheduled time, that day's run starts right after the gap; a repeated hour runs once.

Docker connection and TLS

With no explicit host, HarborBuddy uses the Docker SDK's standard DOCKER_HOST, DOCKER_TLS_VERIFY, DOCKER_CERT_PATH, and DOCKER_API_VERSION variables. To manage a remote daemon over TLS:

environment:
  DOCKER_HOST: tcp://docker.example.net:2376
  DOCKER_TLS_VERIFY: "1"
  DOCKER_CERT_PATH: /certs/client
  HARBORBUDDY_CONTAINER_NAME: harborbuddy
volumes:
  - ./certs/client:/certs/client:ro

Never expose an unauthenticated Docker TCP endpoint. A remote daemon must be reachable from both HarborBuddy and its self-update helper.

Logging

Logs go to standard output as text with RFC 3339 timestamps, or as JSON with HARBORBUDDY_LOG_JSON=true. Colour is used only on a terminal and never when NO_COLOR is set to a non-empty value. HARBORBUDDY_LOG_FILE adds a rotating file. Send SIGUSR1 to toggle debug logging without a restart.

Command-line flags

--config PATH          configuration file
--interval DURATION    override the update interval
--schedule-time HH:MM  override the daily schedule
--timezone ZONE        override the schedule timezone
--once                 run one cycle and exit
--dry-run              pull and report without replacement or cleanup deletion
--cleanup-only         run cleanup and exit
--log-level LEVEL      override the log level
--version              print build information
--healthcheck          check the daemon in this container and exit

Container health check

The image's HEALTHCHECK runs /harborbuddy --healthcheck. The daemon pings Docker every 15 seconds; the check fails when the last successful ping is over 60 seconds old or a cycle has run for over two hours, so monitoring tools see a HarborBuddy that lost Docker or got stuck. One-shot runs (--once, --cleanup-only) do not write the status file, so disable the health check for them with docker run --no-healthcheck.
