Know the boundaries

Limits, requirements, and security

HarborBuddy is built for one standalone Docker Engine and errs on the side of skipping a container rather than recreating it wrong. Know these limits before you let it run unattended.

Docker access is host access

HarborBuddy needs read/write access to the Docker API to pull images and create, stop, rename, start, and remove containers. Anyone who controls the Docker socket controls the host, so treat HarborBuddy as an administrative tool. Run one HarborBuddy per Docker daemon.

Updates cause a brief interruption

The old container stops before its replacement starts. HarborBuddy is not a rolling or zero-downtime updater. Rollback is best-effort, so keep backups of stateful services and opt databases out of unattended updates.

Containers HarborBuddy skips

  • Docker Swarm tasks. Use Swarm's own rolling updates instead.
  • Containers created with auto-remove (--rm).
  • Containers sharing another container's network, PID, IPC, or UTS namespace.
  • Containers whose namespaces another container joins, or that another container links to, such as a VPN gateway used through network_mode: service:gluetun. Update such groups together by hand.
  • Containers created from an image ID rather than a pullable reference.
  • Containers with mounts HarborBuddy cannot reproduce safely.

Compose files are not reread

HarborBuddy recreates containers from Docker's inspection data. It does not call Docker Compose or read your Compose files, so it never changes them. After an update, docker compose up still sees the same configuration.

Private registries

HarborBuddy sends no registry credentials when it pulls, so images that need authentication are not supported yet. Public images on Docker Hub, GHCR, Quay, and other registries work.

Podman

Production use targets Docker Engine. HarborBuddy's integration suite, including updates, rollback, and self-update, also runs against Podman's Docker-compatible API in CI, and Podman-specific behaviour such as the pasta network is handled.
