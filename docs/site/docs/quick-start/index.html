Quick start

Auto-update Docker containers in five minutes

Run HarborBuddy next to your other containers with Docker Compose. Start in dry-run mode, check which containers it would update, then turn dry-run off.

Before you start

  • A Linux host running Docker Engine, with Docker Compose v2.
  • Containers started from pullable image references such as nginx:1.27 or ghcr.io/org/app:stable.
  • Read/write access to the Docker socket. That is effectively root on the host, so treat HarborBuddy like any other admin tool.

1. Create compose.yaml

services:
  harborbuddy:
    image: ghcr.io/mikeo7/harborbuddy:0.1
    container_name: harborbuddy
    restart: unless-stopped
    # Lets an in-progress update finish or roll back on shutdown.
    stop_grace_period: 2m
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
    environment:
      TZ: UTC
      HARBORBUDDY_SCHEDULE_TIME: "03:00"
      HARBORBUDDY_CONTAINER_NAME: harborbuddy
      # Keep the first run observational. Remove after reviewing the logs.
      HARBORBUDDY_DRY_RUN: "true"
    labels:
      com.harborbuddy.role: daemon

This runs every day at 03:00 UTC. Remove HARBORBUDDY_SCHEDULE_TIME to check every 12 hours instead; interval mode runs its first check immediately, while daily mode waits for the scheduled time.

2. Start it and follow the logs

docker compose up -d
docker compose logs -f harborbuddy

3. Preview with a one-off dry run

To see results now instead of waiting for the schedule, run a single dry-run cycle:

docker run --rm --no-healthcheck \
  -v /var/run/docker.sock:/var/run/docker.sock \
  ghcr.io/mikeo7/harborbuddy:0.1 \
  --once --dry-run

Dry-run pulls eligible images so it can compare real image IDs. That uses bandwidth and updates Docker's local image cache, but it never stops, renames, recreates, or removes a container, and cleanup only reports what it would delete.

4. Exclude what should not update unattended

Databases and services with manual migrations are good candidates to opt out. Add a label to their Compose service:

labels:
  com.harborbuddy.autoupdate: "false"

Or deny whole image families, such as postgres:*. See choosing which containers update.

5. Turn on updates

Remove HARBORBUDDY_DRY_RUN and run docker compose up -d again. From then on HarborBuddy replaces a container only when its image ID changes, waits for the replacement to become ready, and rolls back if it does not.

Add health checks to the containers you care about. With a Docker HEALTHCHECK, HarborBuddy waits for healthy before it removes the backup. Without one, it only checks that the process stays up for two seconds.
